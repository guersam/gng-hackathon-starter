# 결정: 체험은 분리하고 실행 법칙만 공유한다

기준일: 2026-08-13
상태: 채택, 해커톤 리허설 뒤 재검토

## 질문

요일·실시간 팀 게임에서 출발한 저장소를, 90분 안에 전혀 다른 게임을 만드는 7팀이 어디까지 재사용해야 하는가?

## 요구와 제약

- 목표: 코더 한 명의 처리량이 아니라 팀 전원이 15분 안에 첫 판을 경험한다.
- 비목표: 모든 게임을 팀/리더보드/WebSocket 모델에 맞추거나 외부 투표 플랫폼을 재구현하지 않는다.
- 대상: 4~5명 × 7팀, 최종 30명, 두 물리적 방, 참가자 소유 Cloudflare 계정.
- 성공 조건: 서로 다른 두 기준 게임이 같은 manifest/정의 계약을 통과하고, 참가자가 하나를 직접 개조하거나 새 팩으로 추가해 바로 플레이하며, import 경계 검사가 역의존을 막는다.
- 제약: 90분, 팀당 AI 코더 한 명일 수 있음, 무료 계정, 모바일 URL 공유.

## 결정

규칙 엔진은 작고 플랫폼과 무관하게 유지하며, 배포와 사용자 흐름은 바깥에서 조립한다.

- `packages/simulation-kit`: 플랫폼을 모르는 상태·행동·사건·투영·수명 계약과 자기 안내 manifest.
- `packages/cloudflare-host`: 명령 멱등성, 사건 추가와 접기 같은 게임 비의존 유틸리티.
- `games/*`: 규칙, 문구, 화면, 단위 테스트와 30명 피날레 계획. 호스트 구현을 import하지 않는다.
- `src/worker`: Cloudflare의 HTTP/WebSocket/SQLite Durable Object 어댑터. 현재 요일 천재의 완전한 운영 구현이며 범용 호스트 전환의 증거 기반 출발점이다.

`pnpm check:boundaries`가 방향을 검사한다. 현재 Handoff Lab은 같은 도메인 계약을 실행하는 로컬 pass-and-play 화면이다. “모든 팩이 이미 네트워크 호스팅된다”고 주장하지 않는다. 공통 원격 호스트 추출은 두 번째 게임이 실제 원격 동기화를 요구할 때만 검토한다.

## 재개방 조건

- 두 후보가 동일한 원격 참가/복구/방송을 구현하느라 코드를 복사한다.
- 30명 피날레에서 pass-and-play가 실제 참여를 막는다.
- 게임별 저장 형식 차이가 공통 호스트의 타입 안전성을 깨뜨린다.

그 전에는 범용 플러그인 프레임워크를 만들지 않는다. 예제→변경→증거 사다리가 추상화보다 우선한다.
