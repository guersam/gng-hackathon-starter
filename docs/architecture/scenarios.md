# 시나리오 포트폴리오

기준일: 2026-08-13

| 식별자 | 장면 | 성공 관찰 |
|---|---|---|
| S1 | 새 Cloudflare 계정의 참가자가 자기 template 또는 fork를 배포한다 | 수동 저장소·비밀값 생성 없이 smoke와 혼자 연습을 마친다 |
| S2 | 서로 다른 정원의 팀들이 준비한다 | 3~5명 정원과 전체 30명 제한이 서버에서 검증되고 선택한 시작 방식대로 한 번만 시작한다 |
| S3 | 한 사람이 문제를 푸는 동안 의무 마감이 지난다 | 문제와 무관하게 누락 인원만큼 정확히 감점되고 사건 순서가 재현된다 |
| S4 | 여러 사람이 마감 경계에서 동시에 입력한다 | 서버 판정이 중복 없이 한 번 정산되고 모든 화면의 점수가 일치한다 |
| S5 | 휴대전화가 잠들었다가 다시 연결된다 | 게임 시간은 계속 흐르고 권한을 재사용해 최신 스냅샷과 누락 사건을 복구한다 |
| S6 | 관리 화면에서 전체 일시정지 후 재개한다 | 활성 시간 기준 마감이 일관되게 이동하고 과거 구간이 두 번 정산되지 않는다 |
| S7 | 30명이 의무·문제·재연결을 섞어 수행한다 | 사건 유실·중복 정산이 없고 리더보드가 일치하며 지연 목표를 리허설에서 측정한다 |
| S8 | 참가자가 점수 규칙 하나를 바꿔 다시 플레이한다 | 테스트, 화면 설명과 성찰 질문이 함께 바뀌고 서버 권위·저장 계약은 유지된다 |
| S9 | 판이 끝나 기록을 함께 본다 | 점수와 시간순 행동 근거가 보이며 사람이나 팀을 진단하는 표현이 없다 |
| S10 | 참가자가 자기 배포에서 혼자 사전 연습한다 | 한 명이 2분 동안 실제 의무·문제·재연결을 거쳐 개인 기록과 비인증 자기 점검을 확인하며 팀 순위에는 들어가지 않는다 |
| S11 | 4~5명 팀에서 한 명만 AI로 코딩한다 | 나머지 구성원이 경험·규칙·플레이·피날레 패킷을 동시에 만들고 15분 안에 모두 첫 입력을 한다 |
| S12 | 요일 게임과 전혀 다른 턴제 게임을 만든다 | 게임 팩이 Worker를 import하지 않고 같은 manifest/결정/접기 계약과 경계 검사를 통과한다 |
| S13 | 7팀이 서로 다른 후보를 교차 플레이하고 투표한다 | 외부 배정·폼을 사용하며 각 플레이어가 관찰 가능한 행동 근거를 하나 남긴다 |
| S14 | 우승 게임을 30명이 두 방에서 실행한다 | 후보가 선언한 피날레 계획대로 60초 안에 입장하고, 완료·실패와 복구 조건을 기록한다 |

극단 입력만 모으지 않는다. 리허설에서는 유난히 순조로운 팀, 급격히 실패한 팀, 회복한 팀의 원시 사건 기록을 보존해 숨은 조건을 찾는다.
